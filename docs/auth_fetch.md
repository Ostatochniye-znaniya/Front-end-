# API Клиент и работа с авторизацией

## Обзор

В проекте реализована централизованная работа с авторизационными запросами через `API клиент`. Клиент полностью управляет токенами, рефрешем и редиректами.

## Основные возможности

- **Авторизация «из коробки»**  
  Если пользователь не авторизован — автоматический редирект на страницу входа с возвратом на исходный URL.
- **Обновление токенов**  
  При истечении токенов клиент пытается их обновить. Если это невозможно — выполняет редирект на авторизацию.
- **Поддержка всех HTTP-методов**  
  GET, POST, PUT, PATCH, DELETE.

## Подключение

```typescript
import { api } from '@/api/client';
```

Все методы API уже содержат встроенную логику авторизации и рефреша.

## Структура сервисов (Services)

**Рекомендуется выносить всю логику запросов в папку `services/`.**  
Это делает код компонентов и страниц чище, а запросы — переиспользуемыми и удобными для тестирования.

### Пример: `getUserData` и `getUserStatus`

В папке `services` находятся сервисы, например:
- `getUserData` — получение данных пользователя
- `getUserStatus` — получение статуса

### Правильная работа с хранилищем (Store/Storage)

Для **редко обновляемых данных** используй хранилище (стор), чтобы избежать лишних запросов на сервер.

Пример подхода (из `getUserData`):

```typescript
// services/getUserData.ts
import { api } from '@/api/client';

export async function getUserData() {
  // Сначала проверяем стор
  const cached = store.get('userData');
  if (cached) return cached;

  // Запрос только при отсутствии данных
  const response = await API.get('/user/data');
  store.set('userData', response.data);
  return response.data;
}
```

## Рекомендации по использованию

✅ **DO (делай так)**  
- Все запросы выноси в `services/`  
- Используй стор для кеширования редко меняющихся данных  
- Полагайся на встроенную логику авторизации — не нужно писать редиректы вручную  

❌ **DON’T (не делай так)**  
- Не размещай вызовы `api.get/post/...` напрямую в компонентах или страницах  
- Не пытайся самостоятельно обрабатывать 401 или рефреш токенов — это уже реализовано в клиенте  

## Пример работы в компоненте

```tsx
// components/UserProfile.tsx
import { getUserData } from '@/services/getUserData';
import { useEffect, useState } from 'react';

export function UserProfile() {
  const [user, setUser] = useState(null);

  useEffect(() => {
    getUserData().then(setUser);
  }, []);

  return <div>{user?.name}</div>;
}
```
